# ProtoHunter 0.5 — Windows x64

## التشغيل

1. استخدم Windows 10 أو Windows 11 بنواة 64-bit.
2. شغّل `ProtoHunter.exe` بالنقر المزدوج؛ لا تحتاج تثبيت Python أو Node.js.
3. تفتح واجهة التحليل في المتصفح. إن لم تُفتح تلقائيًا، انسخ الرابط من نافذة البرنامج.
4. اضغط **«فتح من الجهاز · بدون رفع»** واختر APK/XAPK من نافذة Windows. تُقرأ النسخة الأصلية مباشرة دون نسخها عبر المتصفح، ولا يعدّلها البرنامج. خيار «رفع ملف» متاح أيضًا.
5. اترك نافذة البرنامج مفتوحة أثناء العمل. اضغط Ctrl+C أو أغلقها لإيقاف الخادم المحلي.

الاتصال محلي فقط عبر `127.0.0.1`، على منفذ حر يُختار تلقائيًا. لا يوجد أي مطلب لرفع مصدر بوت أو برنامج آخر. إغلاق تبويب المتصفح وحده لا يوقف البرنامج؛ أغلق نافذة البرنامج أيضًا.

النسخة portable وتحتوي Python والواجهة ومحرك التحليل. لا تحتاج صلاحيات Administrator. يفك المشغّل مكونات التشغيل مؤقتًا داخل مجلد Windows Temp؛ الملفات المرفوعة للتحليل مؤقتة كذلك.

## أوامر اختيارية من PowerShell

```powershell
.\ProtoHunter.exe --version
.\ProtoHunter.exe analyze .\game.xapk --profile games -o .\reports\game.json
.\ProtoHunter.exe analyze .\decoded -o .\reports\decoded.json
.\ProtoHunter.exe doctor
```

## عندك apktool.jar؟

1. افتح **«إعداد Apktool JAR وJava على جهازك»**.
2. اضغط **«اختيار JAR»** وحدد ملفك، حتى لو اسمه `apktool_2.x.jar`.
3. لو Java لم تُكتشف، اضغط **«اختيار Java»** وحدد `java.exe` داخل مجلد `bin` الخاص بتثبيت Java.
4. اضغط **«حفظ وفحص التشغيل»**. تظهر نسخة Java ونسخة Apktool أو رسالة الخطأ الفعلية.
5. اختر **«Apktool · Smali»** من قائمة **فك الكود**، ثم افتح الحزمة.

**ملف JAR ليس Java Runtime**: لو معك JAR فقط، تحتاج تثبيت إصدار Java متوافق مع نسخة Apktool من مصدر موثوق. لا يلزم `apktool.bat` أو ضبط PATH. يمكن أيضًا وضع `apktool.jar` بجوار EXE أو داخل `tools/`؛ يكتشف البرنامج Java من PATH أو JAVA_HOME، أو `tools/java/bin/java.exe` أو `tools/jre/bin/java.exe` بجوار EXE.

يحفظ المسارات في `%APPDATA%/ProtoHunter/tools.json`. لا يتم تشغيل JAR مرفوع كملف تحليل؛ إعداد الأدوات إجراء منفصل محمي ومتاح في واجهة سطح المكتب المحلية فقط. اختر أدوات موثوقة.

```powershell
.\ProtoHunter.exe analyze .\game.xapk --profile games --scan-mode fast --decode apktool --apktool-jar "C:\Tools\apktool.jar" --java "C:\Program Files\Java\jdk-17\bin\java.exe" -o .\reports\game.json
```

**JADX وApktool وJava غير مضمّنة في EXE.** النقر المزدوج يتيح المحركات، لكنه يبدأ بوضع «بدون أدوات خارجية»؛ اختر Apktool صراحةً عند الحاجة إلى Smali. لا تحتاج JADX إذا كنت تريد Apktool فقط؛ JADX اختياري لاسترجاع Java.

## السرعة والتقدم

- الواجهة تبدأ بالفحص **السريع**: يتخطى امتدادات الصور والصوت والفيديو والخطوط وبعض textures ويسجلها في التغطية. مع Apktool يستخدم `-r` لتجنب فك الموارد، مع محاولة فحص سلاسل الموارد مباشرةً.
- **العميق** يضم الوسائط ولا يستخدم `-r` مع Apktool، لكنه أبطأ. لا يعني فهم كل بايت؛ كلا الوضعين له حدود معلنة. CLI افتراضيًا عميق للحفاظ على السلوك السابق.
- الرفع يعرض نسبة نقل حقيقية. التحليل يعرض المرحلة والملف والوقت وعدد الملفات؛ لا توجد نسبة إجمالية تقديرية مضللة. نسب البصمة/فك عضو تخص الملف الحالي فقط.
- يعمل التحليل في الخلفية بدل إبقاء طلب HTTP واحد منتظرًا. زر **إلغاء** يطلب الإيقاف وتنظيف الملفات المؤقتة؛ بعض عمليات القراءة/الفك تؤخر الاستجابة قليلًا.
- فك Smali لحزمة كبيرة قد يظل بطيئًا؛ فك APK خارجي واحد له مهلة 180 ثانية، وحد تشغيل المحركات 8 مدخلات. تظهر المهلات والأخطاء في التقرير.
- تحفظ أحدث مهمتين في ذاكرة الخادم فقط، وتصبح النتائج منتهية الصلاحية بعد ساعة من اكتمالها. صدّر JSON للاحتفاظ بها. إعادة تحميل الصفحة تفقد ارتباطها بالمهمة الحالية؛ إغلاق التبويب لا يوقف الخادم.

اختبار صناعي صغير (ليس لعبة حقيقية): انخفض التحليل العميق من نحو 1.14 ثانية إلى 0.55 ثانية، والسريع إلى 0.08 ثانية مع تخطي صورة واحدة. هذا لا يضمن النسبة نفسها لحزمتك أو لجهازك، ولا يشمل وقت Apktool.

## التحقق من الملف

```powershell
Get-FileHash .\ProtoHunter.exe -Algorithm SHA256
```

قارن النتيجة مع `SHA256SUMS.txt`. الملف **غير موقّع رقميًا**؛ قد يعرض Windows SmartScreen تحذيرًا للناشر غير المعروف. البصمة تكشف تغيّر الملف، لكنها ليست توقيعًا يثبت هوية ناشره. احصل على الملف من مصدر المشروع الموثوق، ولا تعطّل برامج الحماية.

اختُبر الملف التنفيذي آليًا على عامل Windows لبناء المشروع: التشغيل، CLI، فتح الخادم المحلي، ملفات الواجهة، وAPI التحليل الخلفي، وتشغيل JAR صناعي عبر Java لاختبار مسار الربط. حوار اختيار الملفات الحقيقي لم يُختبر تفاعليًا آليًا. هذا لا يعني اختباره على كل إصدارات Windows أو كل حزم الألعاب.

لبيئات الاختبار: `PROTOHUNTER_NO_BROWSER=1` يمنع الفتح التلقائي، و`PROTOHUNTER_PORT` يحدد منفذًا بدل الاختيار التلقائي.
