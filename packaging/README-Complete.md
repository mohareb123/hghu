# ProtoHunter Complete 0.9 — Windows 10/11 x64

## المحركات مرفقة وجاهزة

هذه **الحزمة الكاملة**، وليست EXE صغيرًا يعتمد على تنزيل الأدوات عند أول تشغيل:

- JADX 1.5.3 بالتوزيعة الكاملة.
- Apktool 2.12.1.
- Il2CppDumper مبني من مصدر مثبت مع .NET 8.0.31 مرفق محليًا.
- Java Runtime: Temurin 21.0.12.1+1 مرفقة.

**لا يلزم تثبيت Java أو .NET أو Python أو إعداد PATH أو اختيار مسارات الأدوات.**
فك الضغط إلى مجلد قابل للكتابة، ثم شغّل `ProtoHunter.exe`. احتفظ بمجلد `tools`
وباقي الملفات بجواره. لا تشغّله من داخل ZIP، ولا تنقل EXE وحده.

المحركات تعمل محليًا بعد استخراج الحزمة؛ لا تنزيل لمحركات أو runtimes أثناء
التشغيل. الاتصال بصفحة البرنامج على loopback محلي وليس خدمة سحابية.
استخدم «استوديو المشاريع»: مشروع جديد ← وحدة APK ← المحرك المطلوب ← تعديل
ملفات Apktool ← بناء. وظائف التعديل تحتاج الحزمة المحلية وليست المعاينة العامة.

اختيرت حزمة مجلد portable بدل تضمين مئات الميجابايت داخل EXE ذاتي الفك لتجنب
إعادة استخراج المحركات كل مرة وإبطاء بدء التشغيل. واجهة ProtoHunter موحدة؛
المحركات الأصلية ما زالت برامج مستقلة تقنيًا، لكنها **مرفقة ومدارة تلقائيًا**.

## وضع التحقيق — جديد في 0.9

قبل الفحص اختر **PROTOCOL INVESTIGATION + BOT MODE**. تظهر النقاط وأسبابها
والتصنيفات ومخطط الاستدعاء، مع زر لتنزيل `protocol_report.json` وآخر للمخطط.
BOT MODE اختياري: اختر ملفات أو مجلد مشروعك، ثم Cross-reference، ثم نزّل التقرير
لحفظ المقارنة. لا ينفذ البرنامج ملفات البوت ولا يضمن توافقه مع التطبيق.

الأوزان الموجبة مجموعها **58**، لذا REQUIRED 60+ وCRITICAL 80+ لا يمكن بلوغهما
دون تغيير القواعد. HIGH دليل مسار ثابت، وليس إثبات تشغيل أو انتقال بيانات.
التفاصيل والحدود في `protocol-investigation.md`.

## تصدير الأقسام — جديد في 0.8

بعد الفحص اضغط **↓ كل الأقسام TXT + JSON** لتنزيل ZIP منظم. أمثلة:
`server.txt` و`server.json`، `protocol.txt` و`protocol.json`، وبالمثل
Native وSmali وProtobuf والمصادر والأدلة والتغطية. يشمل التنزيل التقرير كله
ولا يتأثر بالفلاتر؛ `index.json` يربط الأقسام بأسمائها.

«فحص المشروع» ينشئ مجلد `sections` تلقائيًا بجانب `report.json` في مجلد
تشغيل الفحص. افتح مجلد المشروع من الواجهة للوصول إليه. CLI مع `-o report.json`
ينشئ `report.sections`؛ يمكنك تحديد `--sections-dir NEWDIR` بدلًا منه.
المصادر هنا هي المعاينات/المحتوى المتاح في التقرير، لا كل المصدر الأصلي.
المخرجات الكاملة للمحركات تبقى منفصلة في مجلدات عملياتها الأصلية.

## الترقية من 0.6

مسارات المحركات القديمة تُتجاهل افتراضيًا عند اكتشاف الحزمة الكاملة. المشاريع
تبقى في `%APPDATA%/ProtoHunter/Projects`. إن حفظت لاحقًا مسارات يدوية متقدمة،
يمكنك الضغط على «استعادة المحركات المرفقة» للرجوع إلى النسخ المضمنة.
لا تنسخ ملف إعدادات أدوات من مشروع مجهول ولا تستبدل المحركات بملفات غير موثوقة.

## التحقق

```powershell
.\ProtoHunter.exe doctor --verify-bundle
```

يتحقق من SHA-256 لملفات الحزمة؛ قد يستغرق عدة ثوانٍ. افحص نتيجة `ok`.
الحزمة غير موقعة رقميًا؛ البصمات ليست توقيع ناشر. لا تعطّل مضاد الفيروسات.

## حدود صريحة

وجود المحركات لا يعني فك كل حماية أو استرجاع كل كود. Java من JADX ليست مشروعًا
جاهزًا للبناء. Il2CppDumper يستخرج تعريفات/معلومات، لا أجسام C# الأصلية.
التوافق مع metadata المخصصة/المشفرة وإصدارات Unity يظل مقيدًا بدعم المحرك.
البناء يعيد بناء وحدة APK باستخدام Apktool، وليس إعادة بناء Unity native أو
دمج كل splits في APK واحد. راجع `workspaces.md` لباقي حدود المحرر والمشاريع.

**التوقيع فقط** ما زال يحتاج مفتاحك وAndroid SDK Build Tools عند الرغبة في
استخدامه؛ هذه ليست ضمن الأدوات الثلاث المطلوبة أو ضمن الحزمة الحالية.
لا يوجد وعد بأن APK المعدل سيعمل أو سيقبل تحديث التطبيق الأصلي.

## الاختبار والتراخيص

اختبار Windows يشغّل النسخ الحقيقية المرفقة، ويبني APK صناعيًا بـApktool ثم
يفكه بـJADX وApktool من خلال EXE، ويعيد بناءه، ويختبر بدء Il2CppDumper ورفض
metadata غير مدعومة. لا يثبت ذلك استرجاع لعبة Unity حقيقية لم تُقدّم للاختبار.
اختبار التشغيل يستخدم PATH بدون Java/dotnet وبيئة إعدادات جديدة/قديمة للتحقق
من الاكتشاف التلقائي؛ لكنه ليس اختبارًا على كل صورة Windows نظيفة.

التراخيص في `licenses` و`tools/java/legal`؛ التفاصيل في `THIRD-PARTY.md`.
مصادر OpenJDK المقابلة وIl2CppDumper موجودة في artifact منفصل باسم
`ProtoHunter-third-party-sources` في صفحة البناء نفسها، وليست مطلوبة للتشغيل.
