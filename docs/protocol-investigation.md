# Protocol Investigation / BOT MODE — 0.9

## تشغيل الوضع

اختر **PROTOCOL INVESTIGATION + BOT MODE** في خيارات التحليل ثم حمّل APK/XAPK
أو ZIP يجمع الملفات، أو استخدم «فحص الوحدة / التعديلات» في المشروع المحلي.
الفحص المعتاد يبقى خفيفًا، ولا يقرأ تعليمات DEX ما لم يُفعّل هذا الوضع.
المحركات المرفقة يمكن استخدامها لإنتاج Smali أو مصادر إضافية.

```powershell
.\ProtoHunter.exe analyze .\game.xapk --profile games --investigate -o .\reports\game.json
.\ProtoHunter.exe analyze .\game.apk --bot-project .\my-bot.zip -o .\reports\comparison.json
.\ProtoHunter.exe workspace run PROJECT_ID inspect --investigate
```

الخيار `--bot-project` يفعّل التحقيق ضمنيًا، ولا يشغّل أي ملف من المشروع.
واجهة BOT MODE تقبل ملفات مصدر متعددة أو مجلدًا؛ ZIP متاح عبر CLI.

## الجمع والتغطية

مسار الجمع القائم يفهرس الحزم وsplits، `*.proto` وSmali و`classes*.dex` وSO
وManifest وassets/res/unknown، مع عناوين وروابط وبروتوكولات وقرائن تشفير.
أُضيف استخراج IPv6 المنفرد والمُحاط بأقواس. تبقى ميزانيات الحجم والفك والفحص
السريع/العميق والتحذيرات وسجل coverage سارية؛ لا يوجد ادعاء «فهم كل بايت».
`files` و`coverage` يحددان ما قُرئ أو تُخطّي. لم ننسخ كل ملفات APK الخام إلى ZIP
التقرير؛ الأصل محفوظ بالمشروع، ومخرجات المحركات في مجلداتها.

تُقرأ المراجع من كامل نص Smali المفحوص وليس معاينة المصدر المبتورة في الواجهة.
في DEX القياسي 035–040 تُقرأ جداول الأنواع والحقول والدوال والتواقيع وclass_data
وcode_item؛ تُتخطّى payloads حسب أطوالها بدل تفسير بياناتها كتعليمات. أوامر invoke
والحقول والأنواع وconst-string تحمل إزاحة بايت حقيقية. التعليمات غير المدعومة
أو الجداول التالفة تسجّل عدم اكتمال ولا يُختلق منها رسم اعتماد.

## النقاط — جمع خام دون تطبيع أو تكرار

| القاعدة | النقاط | الدليل المستخدم |
|---|---:|---|
| Login/Session caller | +10 | مسار calls من دالة ذات اسم Login/Session/Authenticate؛ الاسم نقطة بداية استدلالية |
| Proto مستخدم كمرجع تعليمة | +8 | تعريف/وراثة Protobuf مع مرجع نوع من خارج عائلة الرسالة؛ constructor مولد وحده غير كافٍ |
| ارتباط بالنقل | +8 | مسار استدعاء إلى API نقل معروفة، لا مجرد كلمة TCP/HTTP |
| Token read/write | +7 | field-access أو استدعاء getter/setter/reader/writer معروف الاسم |
| Server/Region/Account | +7 | field-access أو استدعاء وصول بهذه الأسماء |
| caller/callee | +6 | invoke مباشر من DEX أو Smali |
| Encode/decode | +5 | مرجع استدعاء codec/serialization؛ ليس إثبات أن الناتج باكت شبكي |
| IP/domain/port | +4 | عنوان محمّل بـconst-string في نطاق الدالة؛ ليس إثبات تمريره إلى socket |
| Crypto في مسار نقل | +3 | API تشفير مستدعاة في دالة على السلسلة المرصودة إلى النقل |
| لا مرجع تنفيذي مكتشف | −10 | غياب ضمن الرسم المحدود، وليس إثبات dead code |
| resource فقط | −8 | جميع أدلته في res/assets/unknown/Manifest ولا مراجع تعليمات |
| Proto بلا استخدام مكتشف | −5 | تعريف/مرشح Proto بلا مرجع نوع خارجي مكتشف |

كل قاعدة تُحتسب **مرة واحدة فقط**. `score_reasons` يسجل القاعدة والنقاط والحقل
الذي يحتوي أدلتها. العتبات كما طُلبت: CRITICAL ≥80، REQUIRED 60–79، RELATED
40–59، POSSIBLE 20–39، UNKNOWN 0–19، IGNORE <0.

**المجموع الموجب 58**؛ لا REQUIRED أو CRITICAL في هذه النسخة بهذه القواعد.
HIGH منفصل عن الرقم: مسار ثابت إلى API نقل معروفة، مع عدم وجود غموض تعريفات أو
نقص معروف في رسم التعليمات. ليس احتمالية نجاح، ولا إثبات استدعاء الدالة أثناء
التشغيل، ولا صلاحية للبوت. قد تتضمن السلسلة كودًا ميتًا أو فروعًا لا تُنفذ معًا.

## Dependency Graph

`dependency_graph.json`: عقد بعناوين ثابتة وروابط typed مع الملف والسطر/الإزاحة.
التواقيع كاملة كي لا تندمج overloads. أنواع الروابط تشمل `calls` و`declares`
و`field_access` و`type_use` و`references_type` و`loads_literal` و`declares_field`.
**calls فقط** تدخل في حساب الوصول. مراجع الحقول أو تواجدها في الملف نفسه لا
تتحول إلى روابط نقل بيانات.

`protocol_report.json` يحفظ لكل مرشح الاسم والنوع والنقاط والثقة والأسباب
وreferences والfields ومسار Login والمسار إلى النقل وأدلة API النقل. الواجهة
تعرض السلسلة وروابط الجوار مع أنواعها، وليس سلسلة مختلقة بين طلب ورد لمجرد
تشابه الاسمين. إذا لم يُكتشف Builder أو استدعاء الرد فلن نخترعه.

التصنيفات: AUTH, SESSION, SERVER_DISCOVERY, TRANSPORT, PACKET_CODEC, GAME,
ROOM, MATCH, PLAYER, TEAM, FRIEND, GUILD, CHAT, VOICE, ANALYTICS, TELEMETRY,
UNKNOWN. التصنيف **استدلال اسمي قابل للمراجعة**؛ تقدم التحليلات/telemetry على
كلمات مثل Player داخل أسمائها. `counts` يحصي المرشحين و`proto_message_counts`
يحصي مرشحي Proto فقط، وليس عدد رسائل مؤكدة على الشبكة. قد يبقى تعريف schema
ومرشح class منفصلين إن لم تثبت العلاقة المؤهلة بينهما.

## BOT MODE

اختياري بالكامل. يقرأ أسماء classes/functions/messages، تعيينات وaccessors للحقول،
العناوين ووظائف encode/decode/login/crypto وثوابت opcode/packet_id/command_id.
الأخيرة على جانب APK مدعومة كثوابت Smali مسماة، **لا** استنتاجًا من أرقام عشوائية
أو من أرقام حقول Protobuf. في Native أو DEX بلا ربط ثابت مسمى قد لا تظهر مطابقة.

المقارنة بصمات نصية، لا diff دلالي ولا محاكاة للتنفيذ. الاسم المطابق وحده يصل إلى
0.45 فقط؛ عند اختلافه تُمنح 0.12 لاشتراك كلمات مفيدة. الأوزان الأخرى: fields
0.25، functions 0.10، addresses 0.12، opcodes 0.08، بضربها في Jaccard لمجموعات
الميزات. لا تُرفع درجة تشابه إلى 0.91 لمجرد تشابه كلمة Login.

- CANDIDATE: تشابه ≥0.45 يحتاج مراجعة.
- AMBIGUOUS: أفضل مرشحين متقاربان بفارق أقل من 0.08.
- MISSING: لا مرشح يتجاوز العتبة في الأدلة المفحوصة، لا إثبات إزالة من الإصدار.
- UNRESOLVED: انقطعت المقارنة بميزانيتها قبل العثور على مرشح مقبول.

التقرير يحفظ `bot_matches` و`missing_from_new_version` وأسباب التشابه وأفضل ثلاثة
مرشحين. لا يُعدّل كود البوت تلقائيًا. مقارنة المتصفح تضاف إلى التقرير المحمّل
وتصديره فقط؛ لا تعيد كتابة ملفات sections القديمة في المشروع.

## الحدود والأمان

- 20,000 عقدة، 40,000 رابط، 10,000 مرشح، عمق وصول 24، وحتى 40 دليلًا محفوظًا
  للمرشح. حدود/حالة truncation ظاهرة في التقرير.
- DEX: حتى 200,000 string و32 MiB أحرف مفكوكة و2 مليون تعليمة لكل ملف، مع فحص
  الإلغاء. لا دعم compact/optimized DEX أو graph لتعليمات Native أو Java AST.
- لا تحليل register/taint/data flow، ولا حل reflection/JNI أو dispatch الديناميكي
  أو class loaders. أسماء الدوال المؤهلة عبر الملفات تُربط بنيويًا؛ التعريفات
  المتكررة غامضة. قد تختلف مشاهد الأصل وApktool المعدل.
- BOT MODE: 500 ملف UTF-8، 512 KiB للملف و8 MiB إجمالًا؛ 2000 رمز، 2000 مرشح
  كحد أقصى لكل رمز و200,000 مقارنة إجمالية. بعض اللغات تُقرأ استدلاليًا لا بمحلل AST.
  المجلد يتخطى symlinks و.git/node_modules/بيئات البناء؛ ZIP يُقرأ دون استخراج.
- لا تُشغّل الملفات ولا تُتصل العناوين المستخرجة. انتبه لوجود أسرار/رموز في النتائج.
  ملفات المتصفح تُرسل إلى خادم الأداة المستخدم؛ EXE المحلي يبقيها على الجهاز.
- `POST /api/bot-compare` يقبل فقط `{protocol_report, files:[{name,text}]}`، وليس
  مسارات ملفات الخادم. حد الطلب 32 MiB؛ طلبات cross-origin مرفوضة، وslot واحد
  للمقارنة/التصدير. اختيار ملفات البوت لا يُنفذ أوامر ولا يستدعي المحركات.

الاختبارات fixtures وليست تقريرًا عن لعبة مستخدم لم تُقدَّم. لا ضمان لفك الحماية
أو استرجاع المصدر الكامل أو توافق بروتوكول مع بوت.
