# ProtoHunter Studio 0.6 — دمج عملي، وليس إعادة كتابة المحركات

هذا إصدار أول لمساحة مشاريع توحّد **JADX / Apktool / Il2CppDumper** وتضيف دورة تعديل وبناء وتوقيع. لا يدّعي استنساخ كل خصائص واجهات الأدوات الثلاث، ولا فك أي حماية أو استرجاع كل الكود.

## ما تم تنفيذه

| المسار | التنفيذ | الحدود المهمة |
|---|---|---|
| JADX | تشغيل CLI، حفظ Java الناتجة، عرضها والبحث فيها وربط أدلتها بالتقرير | Java تقريبية وللقراءة؛ ليست مدخل إعادة بناء التطبيق |
| Apktool | فك كامل للـSmali والموارد والـManifest، تحرير النصوص، diff، نسخ احتياطية واستعادة، إعادة البناء | الملفات الحالية الناتجة عن Apktool فقط قابلة للتحرير؛ لا محرر binary أو dex assembler مستقل |
| Il2CppDumper | اكتشاف libil2cpp.so وglobal-metadata.dat عبر APK/splits، اختيار الزوج صراحةً، تشغيل EXE أو DLL عبر dotnet، حفظ dump.cs وDummyDll والمخرجات المساندة | لا يستعيد أجسام دوال C# الأصلية، ولا يعيد بناء native/Unity؛ لم ننفّذ تفريغ ذاكرة أو فك تشفير تلقائي |
| الفحص | يجمع فحص APK/Smali الحالي مع أحدث مخرجات JADX وIL2CPP الناجحة للوحدة المحددة في لوحة الأدلة | المخرجات المشتقة ليست بايتات أصلية إضافية. Java/Unity من الأصل قد تختلف عن Smali المعدلة |
| التوقيع | zipalign ثم apksigner sign ثم verify والتحقق من المحاذاة | يحتاج Android SDK Build Tools حديثة ومفتاحك؛ لا يسترجع توقيع الناشر ولا يضمن التثبيت/عمل التطبيق |

## إعداد الأدوات

افتح EXE ثم **«إعداد محركات JADX وApktool وIL2CPP والتوقيع»**:

- **Apktool:** ملف `apktool.jar` وJava متوافقة؛ لا يلزم BAT.
- **JADX:** اختر `bin/jadx.bat` من **التوزيعة الكاملة** أو اكتب مسار مجلدها. عند وجود `lib/*.jar` يستخدم البرنامج Java مباشرةً مع `jadx.cli.JadxCLI`. اختيار launcher وحده دون بقية التوزيعة غير كافٍ.
- **Il2CppDumper:** اختر `Il2CppDumper.exe` مع إبقاء ملفات توزيعتِه بجواره، أو `.dll` مع تحديد `dotnet.exe` وإصدار .NET المتوافق. اجعل `RequireAnyKey` مساويًا `false` في `config.json` بجوار الأداة؛ العمليات غير تفاعلية ولا ترسل إجابات تخمينية لو طلب المحرك عناوين/بيانات إضافية.
- **التوقيع:** اختر `zipalign.exe` ويفضّل `lib/apksigner.jar` من Android SDK Build Tools حديثة تدعم `zipalign -P 16`.
- اضغط حفظ وفحص. فحص النسخ يشغّل Java/Apktool/JADX فقط؛ Il2CppDumper لا يُشغّل دون مدخلات لأنه ليس له أمر version-only مماثل. ظهور المسار متاحًا لا يثبت توافقه مع لعبتك.

المحركات وJava و.NET وAndroid SDK **غير مضمّنة أو محمّلة تلقائيًا**. استخدم التوزيعات الرسمية الموثوقة؛ كل أداة وترخيصها مستقلان:
[JADX](https://github.com/skylot/jadx)، [Apktool CLI](https://apktool.org/docs/cli-parameters/)، [Il2CppDumper](https://github.com/Perfare/Il2CppDumper)، [apksigner](https://developer.android.com/tools/apksigner)، [zipalign](https://developer.android.com/tools/zipalign).

## دورة العمل في الواجهة

1. من **استوديو المشاريع** اضغط «مشروع جديد من APK/XAPK». تُنسخ الحزمة إلى مشروع مستقل وتُحسب بصمتها؛ الملف الذي اخترته لا يُعدّل. هذا الاستيراد الدائم يختلف عن خيار الفحص السريع «بدون رفع» وقد يحتاج مساحة ووقتًا إضافيين.
2. اختر **وحدة APK**. الحزم تحتوي وحدات منفصلة ولا نفترض أن أول عضو هو base.
3. شغّل JADX للقراءة وApktool للتحرير. كل تشغيل يكتب في مجلد جديد؛ إعادة فك Apktool تجعل النسخة الجديدة الحالية وتحتفظ بالتعديلات القديمة في مجلد التشغيل السابق.
4. لملفات Unity: اكتشف الملفات وحدد المعمارية وmetadata من الإصدار نفسه؛ يمكن أن يكونا في split مختلفين. التشغيل اليدوي للأداة قد يلزم للحالات التي تحتاج تدخلًا أو إعدادات متخصصة.
5. افتح ملف Smali/XML، عدّل، اعرض الفرق ثم احفظ. الحفظ يرفض النسخة القديمة إذا تغيّر الملف منذ فتحه ويحتفظ بنسخة احتياطية. زر الاستعادة يُنشئ سجل تعديل جديدًا أيضًا.
6. «فحص الوحدة / التعديلات» يعرض التقرير في لوحة البحث الحالية ويحفظ `report.json` ضمن التشغيل.
7. ابنِ APK. الناتج **غير موقّع** ويمثل الوحدة المحددة فقط.
8. لو أردت التوقيع: أدخل keystore الخاص بك وalias وكلمة المرور محليًا، ثم شغّل المحاذاة والتوقيع والتحقق. كلمات المرور لا تُكتب في `project.json` أو أوامر التنفيذ أو إعدادات الأدوات؛ تُمرر عبر متغيرات بيئة خاصة بالعملية وتُمسح حقولها من الواجهة عند البدء.
9. «فتح مجلد المشروع» يوصلك إلى APK وملفات المخرجات والسجلات. كل APK داخل مجموعة splits يحتاج توقيعًا متوافقًا بالمفتاح نفسه. **لا توجد حاليًا إعادة تجميع XAPK موحّد أو تثبيت على الهاتف أو إدارة ADB.**

التوقيع الجديد لا يسمح بتحديث نسخة تحمل شهادة مختلفة. صحة التوقيع لا تضمن توافق منطق التطبيق أو الموارد أو الـsplits. البرنامج يرفض توقيع بناء قديم بعد تعديلات محفوظة جديدة؛ التغييرات اليدوية خارج البرنامج مسؤوليتك.

## التخزين والحدود

`%APPDATA%/ProtoHunter/Projects/<id>/` على Windows؛ أو `~/.config/ProtoHunter/Projects` في الأنظمة الأخرى. المشاريع دائمة ولا تُحذف بانتهاء جلسة الخادم. افتح مجلد المشروع للنسخ/الأرشفة أو الإزالة يدويًا بعد إيقاف العمل عليه.

- أصل الحزمة: 2 GiB؛ فك أعضاء XAPK: 4 GiB كحد إجمالي و32 APK و40 ألف إدخال.
- أعضاء Unity المحددة: 512 MiB لكل ملف مع رفض التشفير/نسب الضغط الشديدة.
- تحرير UTF-8 حتى 1 MiB؛ الأكبر معاينة جزئية للقراءة. لا تعديل للأصل أو Java/Unity أو الملفات الثنائية في المحرر.
- قائمة حتى 20 ألف ملف، وعرض 300 في المرة (استخدم التصفية). بحث نصي حرفي، لا regex: حتى 5 آلاف ملف/64 MiB/300 تطابق، مع إعلان التخطي أو الاختصار.
- حتى 200 تشغيل و1000 تعديل لكل مشروع. التقرير داخل الواجهة حتى 64 MiB؛ الأكبر متاح في مجلد المشروع.
- مهلة كل خطوة محرك 15 دقيقة، وحد سجلها 16 MiB مع عرض ذيل مباشر وإلغاء. مخرجات الفشل والإلغاء محفوظة وموسومة، وليست نجاحًا.
- إذا أُغلقت العملية فجأة قد يبقى تشغيل موسومًا `running` في التاريخ؛ هذا آخر وضع محفوظ، وليس إثبات أنه ما زال نشطًا. أقفال نظام التشغيل تتحرر عند خروج العملية.
- لا يوجد sandbox أو حد شامل لمساحة/ذاكرة أدوات الطرف الثالث. فك الحزم المعقدة قد يستهلك جيجابايتات. الأدوات اختيارات تنفيذ موثوقة؛ يُفضّل بيئة معزولة للحزم غير الموثوقة.

واجهات المشاريع محمية برمز الجلسة وHost loopback ومراجعة Origin. لا تُتاح للمعاينة العامة. واجهة الفحص العامة السابقة ليست خدمة مصادقة متعددة المستخدمين. لا تعرض الخادم على شبكة غير موثوقة.

## CLI

```powershell
# إعداد المسارات من الواجهة محفوظ؛ يمكن تجاوزها هنا قبل create/run.
.\ProtoHunter.exe workspace create .\game.xapk
.\ProtoHunter.exe workspace list
.\ProtoHunter.exe workspace show PROJECT_ID
.\ProtoHunter.exe workspace --apktool-jar "C:\Tools\apktool.jar" run PROJECT_ID apktool --unit unit-001
.\ProtoHunter.exe workspace --jadx "C:\Tools\jadx" run PROJECT_ID jadx --unit unit-001
.\ProtoHunter.exe workspace run PROJECT_ID inspect --unit unit-001
.\ProtoHunter.exe workspace run PROJECT_ID build --unit unit-001
.\ProtoHunter.exe workspace --il2cpp "C:\Tools\Il2CppDumper\Il2CppDumper.exe" run PROJECT_ID il2cpp --unit unit-002 --binary-unit unit-002 --binary-member "lib/arm64-v8a/libil2cpp.so" --metadata-unit unit-001 --metadata-member "assets/bin/Data/Managed/Metadata/global-metadata.dat"
```

لـAPK منفرد معرف الوحدة `main`. `workspace --root PATH` يغيّر مكان حفظ المشاريع. يدعم CLI `sign --keystore PATH --alias NAME --store-pass-env VARIABLE --key-pass-env VARIABLE`؛ أسماء المتغيرات فقط تظهر في الأمر. لا تضع كلمات المرور حرفيًا في سجل أوامر الشِل أو المحادثة؛ استخدام حقول الواجهة المحلية أبسط.

## ما اختُبر وما لم يُختبر

اختبارات الوحدة وHTTP تفحص دورة المشروع، الاقتران عبر splits، الفروق والنسخ والاستعادة، منع traversal/symlinks، قفل المشروع، الأذونات، إلغاء العمليات، عدم تسجيل كلمات المرور، وفشل المحركات. اختبارات المتصفح تختبر الدورة كاملة باستخدام **محركات تجريبية مصغرة**؛ ليست إثباتًا لفك لعبة حقيقية أو توقيع APK حقيقي بهذه المحركات التجريبية.

اختبار EXE على Windows يفحص الملف المجمد نفسه، CLI، استيراد مشروع وفحصه، والواجهة وAPI، وJAR صناعي عبر Java. لم تُقدّم حزمة لعبة حقيقية للتحقق من توافق الأدوات الثلاث معها. لا يوجد ضمان لاسترجاع المنطق بنسبة 100% أو لتعديل Unity native من تعريفات DummyDll.
