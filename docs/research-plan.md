# خطة فحص Login → Session → Game

الإصدار `freefire-research-v1` مبني على أهداف المستخدم. هذه **قائمة بحث**، وليست schemas أو أسماء مؤكدة لكل إصدار من فري فاير. يلزم APK/XAPK فعلي للتحقق من وجودها. لا يتضمن المشروع أي ملفات لعبة مملوكة أو مفاتيح حقيقية أو اتصالًا بسيرفرات اللعبة.

## 1. Login والإعدادات

البحث عن:

- `CSMajorLoginReq` و`CSMajorLoginResp`.
- `http.proto`.
- `N2/c.smali` و`LP2/c.smali`، بما يشمل class descriptors مثل `LN2/c;`.
- `VodkaConfig`.
- أسماء `appKey` و`appSecret` و`serverId`، وكذلك Login/authentication.

كل نتيجة تحدد الملف، السطر أو offset، مقتطف الدليل، والكلاس والدالة إذا كان المدخل Smali. **وجود اسم حقل لا يعني استرجاع قيمته أو فك مفتاح مشفّر.** التقرير والمعاينات قد يحتويان ثوابت حساسة من المصدر نفسه؛ تجنب مشاركتهما علنًا.

## 2. بيانات الجلسة

البحث عن `token` و`accountId` و`region` و`serverTimestamp` و`GetLoginData`، مع صيغ snake_case وget/set/has/clear الشائعة.

- قائمة `research` تعرض المراجع النصية.
- قائمة `flow` تعرض تعليمات Smali `invoke-*` الفعلية ذات الصلة، مع caller وcallee.
- لا تُعامل تعليقات Smali أو النصوص التي تشبه التعليمات كاستدعاءات فعلية.
- **هذه ليست data-flow analysis**: لا يُثبت أن token معيّن انتقل من Login إلى GetLoginData أو إلى سيرفر لاحق. ولا يُثبت ترتيب التنفيذ أو قابلية الوصول أو مسار نجاح المصادقة.
- DEX المباشر يقرأ جدول السلاسل فقط؛ لا ينتج مراجع تعليمات DEX أو call graph. للحصول على مراجع Smali من APK فعّل Apktool أو حلّل مجلدًا مفكوكًا مسبقًا.

## 3. TCP / Game connection

البحث عن `prototcp/` و`account.proto` و`signalingservice.proto` ومؤشرات `socket` و`connect` و`host` و`port` و`send` و`recv`.

- المنافذ داخل URLs أو IPv4:port تحفظ مباشرة ضمن أدلة العنوان.
- إسناد رقمي بسيط لحقل `port` مثل `port:I = 0x1f90` يظهر كـ `port_literal_candidate`.
- إسناد نصي بسيط لـ `region` يظهر كـ `region_literal_candidate`.
- كلاهما **غير مرتبط تلقائيًا بـ endpoint** (`bound_to_endpoint: false`).
- أرقام حقول `.proto` لا تُعامل كقيم منافذ.
- وجود Socket API لا يكفي لتحديد TCP مقابل UDP أو إثبات حصول اتصال.

## 4. رسائل اللعبة

البحث عن عائلات `Player / Team / Chat / Room / Match / Friend / Guild / Inventory`، مع الاحتفاظ بالاسم الكامل، مثل `CSPlayerInfoReq` أو `GuildInfo`.

- تصنيف الاسم وحده هو `message-family candidate` منخفض الثقة؛ قد يكون كلاس واجهة أو نموذج بيانات غير شبكي.
- إذا وُجدت schema/descriptor، يعرض قسم Protobuf بنيتها المعروفة دون اختراع أنواع الحقول المفقودة.
- استخراج اسم الرسالة لا يثبت opcode أو packet framing أو crypto أو أنه قابل للإرسال إلى اللعبة.

## 5. اختيار السيرفرات ذات الصلة

كل العناوين تظل متاحة للمراجعة، ويُضاف فلتر **ذو صلة بخطة البحث**. أسباب الترشيح منفصلة:

| السبب | ما يعنيه | ما لا يعنيه |
|---|---|---|
| `endpoint_name_hint` | الاسم يتضمن login/auth/game/match… | ليس إثبات دور الخادم |
| `same_smali_method_as_research_reference` | العنوان والهدف ظهرا في نفس دالة Smali | ليس تتبع قيمة أو اتصال فعلي |
| `explicit_transport_scheme` | وجود tcp/udp/ws/wss في النص | لا يثبت تنفيذ الاتصال |
| `same_file_as_research_reference` | اشتراك الملف فقط | ضعيف جدًا؛ **لا يكفي وحده لإدراج العنوان في الفلتر المركّز** |

تجميع المضيفين يحتفظ بالأدلة من ملفات مختلفة، لكنه لا يدمج region أو port غير مرتبطين بمجرد قرب النصوص.

## التغطية: لماذا لا نكتب «100%»؟

المسار الشائع:

```text
XAPK/APKS
├── base.apk
│   ├── AndroidManifest.xml
│   ├── classes*.dex
│   ├── lib/<abi>/*.so
│   ├── assets/
│   ├── res/
│   └── unknown/
├── asset packs / OBB
└── configuration splits
```

لا توجد قائمة مجلدات تُستثنى من الحزمة في محرك التطبيق؛ يُفحص المحتوى المقروء ضمن ميزانيات الموارد والأمان. لكن الملفات الكبيرة جدًا أو عالية الضغط أو التالفة أو المشفّرة أو الأرشيفات فوق حد العمق يمكن أن تكون غير مفحوصة/غير مفكوكة، ويظهر ذلك في التقرير.

### ثلاثة أشياء مختلفة

1. **حصر الملفات:** معرفة أعضاء الأرشيفات التي أمكن فتحها. إذا تعذر فتح أرشيف متداخل، فمحتواه غير معروف. لا يخفي التقرير ذلك وراء نسبة اكتمال.
2. **قراءة البايتات:** SHA-256 للمدخل الأصلي ولكل ملف محتوى قُبل للفحص، بما في ذلك البايتات غير النصية. `bytes_hashed` يوضح نطاق القراءة. بصمة XAPK تقرأ الملف المضغوط، ولا تعني فك محتوى كل عضو.
3. **استخراج الدلالات:** DEX strings، سطور Smali، ELF symbols، string pools، descriptors… كل طريقة لها حدود؛ البصمة لا تفك تشفيرًا ولا تفهم التعليمات أو كل صيغة ملف.

قسم `coverage` يسجل `status / reason / methods / size / bytes_hashed / sha256`:

- `scanned`: نُفذت طرق الاستخراج المذكورة، لا أن كل المنطق مفهوم.
- `partial`: خطأ parser أو بلوغ حد نتائج/بنية، وقد تكون بصمة البايتات كاملة.
- `skipped`: عضو معروف لم يُقرأ؛ السبب موضح.
- `error`: عضو معروف تعذر قراءته.
- `enumerated`: حاوية تم المرور على دليلها، وليس ضمان قراءة أبنائها جميعًا.
- `unexpanded`: حاوية لم يمكن فتح محتواها.
- `inventory_incomplete`: توقف الحصر؛ عدد الأعضاء المباشرة غير المسجلة يذكر عندما يكون معروفًا.

`coverage_summary` لا يجمع أحجام الحاويات المتداخلة مع أحجام محتوياتها؛ بصمة المدخل الجذري منفصلة. ملفات فك الكود الناتجة عن JADX/Apktool قد تزيد عدد الملفات المفحوصة، ولا يمثل مجموع أحجامها حجم APK الأصلي. سجل التغطية محدود بـ100,000 صف، مع عدّ للصفوف المحذوفة إن بلغ الحد.

**`semantic_completeness_guaranteed` دائمًا `false`.** لا يوجد وعد بفهم 100% من كل بايت، أو استرجاع أسرار/اتصالات ديناميكية أو ملفات مخفية دون مفتاحها.

### AndroidManifest.xml وresources.arsc

يقرأ المحرك string pools في Android Binary XML وجداول الموارد، UTF-8 وUTF-16، ضمن فحص نطاقات صارم. هذا أفضل من الاعتماد على ASCII carving فقط، لكنه **ليس فك Manifest كاملًا**: لا يستعيد شجرة XML أو يربط أسماء الخصائص بقيمها المرقّمة. حدود القارئ: 200,000 سلسلة، 32 KiB لكل سلسلة وعمق 4 للكتل المتداخلة. استخدم Apktool للموارد المفكوكة إن توفر.

## حدود النتائج الموجّهة

- حتى 20,000 نتيجة بحث مستقلة عن حد النتائج العامة 15,000؛ لا يوقف امتلاء النتائج العامة البحث الموجّه تلقائيًا.
- حتى 10,000 مرجع استدعاء Smali موجّه، مع علامة عند بلوغ الحد.
- الأسماء والحقول المستخرجة من descriptors تُبحث أيضًا بعد parsing، فلا تعتمد المطابقة بالكامل على حدود السلاسل الثنائية الخام.
- الكلمات القصيرة مثل AES وTCP وUDP تُفحص ضمن ASCII/UTF-16 carving ابتداءً من 3 أحرف، مع احتمال ضوضاء أكبر؛ الدليل والدرجة يظلان ظاهرين.

## ما يلزم للتحقق على فري فاير

1. حزمة XAPK أو APK مع splits ومواردها المتاحة، لنسخة تملكها أو لديك إذن بتحليلها.
2. JADX وApktool مثبتان إن أردت Java/Smali مفكوكًا، أو مجلد مفكوك مسبقًا.

بدون هذه الملفات تظل الاختبارات صناعية. لا يُنسب أي Login endpoint أو Game server أو schema بعينها للعبة لمجرد وجود الاسم ضمن خطة البحث.
